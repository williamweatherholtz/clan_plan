## P0 — actively broken or about to bite

### 1. JSON API routes only check "is the reunion loaded" — not "is this user a member"
Authorization is broken across the JSON API. Most mutating handlers call only
`load_reunion(&state, reunion_id).await?` and never gate by membership. Any
logged-in user who knows (or guesses) a reunion UUID can read, write, RSVP,
comment, upload media, list expenses, etc. on a reunion they have no
relationship to.

Evidence (non-exhaustive):
- `src/routes/activities.rs:34-38` `list_activities` — no membership check.
- `src/routes/activities.rs:60-78` `create_activity` — no membership check.
- `src/routes/activities.rs:130-149` `create_comment` — no membership check.
- `src/routes/activities.rs:152-160` `delete_comment` — no membership check.
- `src/routes/activities.rs:170-200` `update_comment` / `set_status` — no membership check.
- `src/routes/activities.rs:339-349` `list_comments` — no membership check (anyone reads any comments).
- `src/routes/activities.rs:391-413` `rsvp_activity` / `unrsvp_activity` — no membership check.
- `src/routes/expenses.rs:29-45` `list_expenses` — no membership check (financial data leak).
- `src/routes/expenses.rs:81-95` `get_balances` / `get_balances_csv` — no membership check.
- `src/routes/expenses.rs:128-145` `confirm_expenses` / `unconfirm_expenses` — no membership check.
- `src/routes/feedback.rs:69-79` `list_survey_questions` — no membership check.
- `src/routes/media.rs:24-101` `upload_media` — no membership check (anyone can dump files into any reunion's storage).
- `src/routes/media.rs:108-117` `list_media` / `download_media` / `download_all_zip` — no membership check.
- `src/routes/availability.rs:23-30` `get_my_availability` — no membership check.
- `src/routes/today.rs:43-66` `get_today` / `get_ics` — no membership check.
- `src/routes/reunions.rs:60-66` `list_reunions` — returns every reunion in the DB to any logged-in user, including Draft phase ones.
- `src/routes/reunions.rs:91-97` `get_reunion` — no membership check.

The HTML page handlers go through `helpers::load_reunion_for_member` and are
fine. The JSON `/api` surface skipped that step. The bug is structural — the
extractor `CurrentUser` is the only gate, and `load_reunion` was never
intended to authorize.

Fix: add a new extractor `ReunionMember { user, reunion }` that resolves the
`:id` path param, checks `user_is_reunion_member`, and returns
`AppError::Forbidden`/`NotFound` otherwise. Replace every
`load_reunion(...).await?` in `src/routes/*.rs` with that extractor as a
function argument. Where the route is RA-only, layer
`ensure_ra` on top inside the handler (or add a `ReunionRa` extractor).
Do NOT rely on `load_reunion` alone — its docstring should be updated to
say "loads a reunion; does NOT authorize."

### 2. Activity DELETE leaks the deleted record through a non-transactional fallthrough
`src/routes/activities.rs:289-321` `delete_activity` deletes the
`activity_idea` first, then conditionally deletes the linked
`schedule_blocks` row in a *separate* statement. If the second query fails
(connection drop, deadlock), the idea is gone but the schedule block lives
on with a dangling `promoted_to_block_id` reference that points to nothing.
Fix: run both deletes inside a single `pool.begin()` transaction, or — far
better — declare `activity_ideas.promoted_to_block_id` with `ON DELETE
CASCADE` going the *other* direction (delete the idea triggers the block
delete) via a new migration. Pick the latter to avoid the application-layer
gymnastics.

### 3. Login rate limiter is bypassable by rotating email
`src/routes/auth.rs:165-176` and `src/models/login_attempt.rs:21-44`: the
limiter counts failures by email only. An attacker who knows nothing rotates
through `a@x`, `b@x`, … and never hits 10 failures on any single key. There
is also no IP-based limit despite the schema having an `ip` column and an
`idx_login_attempts_ip_time` index ready for the query
(`migrations/015_login_attempts.sql:10`). Fix: change
`LoginAttempt::recent_count` to also count by IP and lock out when either
key exceeds `MAX_FAILURES`. The IP comes from `extract_ip(&headers)` which
already exists in `auth.rs:191-198`.

### 4. `login_attempts` table grows unboundedly
No cleanup job, no TTL, no janitor. Every failed login is a permanent row.
`src/models/login_attempt.rs` ships only `record` and `recent_count`; nothing
deletes old rows. After a year of low-rate scanning the
`idx_login_attempts_email_time` index alone will be enormous and
`recent_count` slows down. Fix: add either (a) a `DELETE FROM login_attempts
WHERE attempted_at < NOW() - INTERVAL '7 days'` background task on app
start, or (b) a partitioned table dropping old partitions, or (c) — simplest
— delete inside `record` when count > N rows for the same email.

### 5. `download_all_zip` loads every reunion file into memory
`src/routes/media.rs:182-228` builds the entire ZIP in a `Vec<u8>` before
returning. With a 25-MB-per-file cap and 100 photos, that's 2.5 GB of
RAM per request. Worse, while the buffer is being built every other request
on the runtime can be starved (zip writes are sync and the loop is awaited
between reads but the zip ops are CPU-bound). Fix: stream the response with
`axum::body::Body::from_stream` over a `tokio_util::io::ReaderStream` driven
by an `async-zip` writer that flushes incrementally, OR cap the zip endpoint
to N MB and reject larger reunions with a "use individual downloads" error.
For the v1 fix, at minimum spawn the zip build inside
`tokio::task::spawn_blocking` so the runtime isn't blocked.

### 6. `main.rs:48-58` unwraps a redirect response
`Response::builder()....body(Body::empty()).unwrap()` in
`redirect_to_canonical_path`. This is a guaranteed-safe unwrap *today* (an
empty body never fails), but the pattern teaches bad habits and one future
edit (e.g. adding a header from a parsed string) will turn this into a 500.
Fix: switch to `Redirect::permanent(&location).into_response()` — it does
the same thing without the `.unwrap()`.

### 7. Media uploader blocks the async runtime on cleanup
`src/routes/media.rs:96-100`: the cleanup path uses
`std::fs::remove_file(&abs_path)` (sync) inside an async fn. On a heavily
loaded server this can stall the runtime worker for the duration of the
syscall. Fix: `tokio::fs::remove_file(&abs_path).await.ok();`.

## P1 — real design problems, fix before they grow

### 8. `pages.rs` is 2,105 lines and counting
`src/routes/pages.rs`: a god module. It mixes template structs, view structs,
extractors (`SlugOrId`), middleware-ish helpers (`require_login`,
`require_sysadmin`), flash plumbing, asset embedding, the calendar builder,
and 14+ page handlers. Every new page touches this one file, and reviewer
context explodes on PRs.
Fix: split per-domain. Concrete plan:
- `src/routes/pages/mod.rs` — top-level routing + extractor wiring.
- `src/routes/pages/views.rs` — all the `*View` / `*PageView` structs.
- `src/routes/pages/auth.rs` — login/register/forgot/reset/profile.
- `src/routes/pages/dashboard.rs` — dashboard + admin.
- `src/routes/pages/reunion.rs` — overview + settings + join.
- `src/routes/pages/tabs.rs` — `reunion_tabs`, `NavTab`, `CalendarMonth`.
- One file per tab: `activities.rs`, `availability.rs`, `expenses.rs`,
  `locations.rs`, `media.rs`, `schedule.rs`, `survey.rs`, `today.rs`.

### 9. N+1 query patterns everywhere a list renders
- `src/routes/expenses.rs:33-46` — list expenses then `for { fetch splits }`.
- `src/routes/schedule.rs:52-68` — list blocks → loop slots → loop signups.
- `src/routes/pages.rs:1559-1574` — same N+1 pattern in `schedule_page`.
- `src/routes/pages.rs:1635-1715` — `activities_page` runs the rsvp query
  *and* the proposer query *per activity*; a reunion with 40 ideas does
  80 round trips.
- `src/routes/pages.rs:1471-1499` — `locations_page` loops
  `LocationVote::aggregate_for_candidate` once per candidate.

Fix: pull data with a single join in each `*::list_for_reunion_with_*`
helper on the model, return a flat `Vec<RowView>`, group in Rust. The
`top_activity_rows` query at `src/routes/pages.rs:1278-1311` already shows
the pattern is workable.

### 10. `Reunion::list_all` leaks Draft reunions to non-members
`src/routes/reunions.rs:60-66` returns every reunion in the database to
every logged-in user. The `dashboard` page (`src/routes/pages.rs:984-1009`)
filters in Rust after fetching all of them, which both leaks Draft data via
the raw API and scales O(reunions × users) per dashboard load. Fix: push the
filter into SQL — `Reunion::list_accessible(pool, user_id, is_sysadmin)` —
and make `/api/reunions` call the same gated query. Drop the public
`list_all` from the API entirely.

### 11. View-struct pattern is inconsistent; templates do raw model traversal
The codebase has both:
- View structs that flatten model state for the template
  (`ScheduleSlotPageView`, `ActivityPageView`, `LocationPageView`) — fine.
- Direct model field access from templates
  (`templates/pages/activities.html:95` reads `a.idea.status.label()`, and
  several places reach into `reunion.slug`, `reunion.phase`).

Pick one. Either the template renders flat view structs (so `status` is a
`String` already and the template never calls methods), or it consumes
models. Mixing both means a model rename ripples through templates the
compiler can't help with. Recommend: every `*PageView` flattens to
template-friendly primitives; templates never call methods on enums.

### 12. `unwrap_or_default()` swallows database errors silently across `pages.rs`
61 occurrences of `unwrap_or`/`unwrap_or_default`/`unwrap_or_else` in
`src/routes/pages.rs`. The pattern below appears dozens of times:
```rust
let admin_rows: Vec<...> = sqlx::query_as(...)
    .fetch_all(state.db()).await
    .unwrap_or_default();
```
A DB failure becomes "the user just sees no RAs listed" — silent broken UI,
no log, no alarm. Fix: convert to `?` and let `AppError::Database` propagate
to the existing tracing path (`error.rs:52`). The handler signature is
already `Result<Response, Response>` in most cases. For the few places
where "empty result is fine" is the actual product decision, write
`.unwrap_or_else(|e| { tracing::warn!("X failed: {e:?}"); Vec::new() })`
explicitly so the failure is visible.

### 13. Magic strings for roles, categories, statuses sprinkled through SQL and Rust
- Activity category strings `"group" | "optional" | "meal"` appear inline in
  `src/routes/activities.rs:96`, `src/routes/pages.rs:1665`,
  `src/models/activity.rs:78`, and the HTML template
  (`templates/pages/activities.html:101-109`).
- RSVP role strings `"in" | "make" | "cleanup"` appear in
  `src/routes/activities.rs:373-388`, `src/routes/pages.rs:1655-1685`,
  `src/routes/helpers.rs:113`, and in `migrations/018_activity_rsvp_roles.sql`.
- Phase labels appear both in `Phase::label()` and as raw strings in
  templates (e.g. `phase_label: r.phase.label().to_string()` then the
  template compares strings).

Fix: define `enum ActivityCategory { Group, Optional, Meal }` with
`sqlx::Type`-style `#[sqlx(type_name = "...")]` *or* as a Rust enum the
model converts to/from `&str` in a single place. Same for `RsvpRole`. Use
the enum everywhere; never compare strings in templates.

### 14. Auth checks duplicated across every page handler
Every reunion page handler repeats:
```rust
let user = require_login(&session, &state).await?;
let reunion = helpers::load_reunion_for_member(&state, &user, reunion_id).await?;
let flash = take_flash(&session).await;
let is_ra = helpers::user_is_ra(&state, &user, reunion_id).await;
```
14 page handlers, copy-pasted. Each adds one round trip to `users`, one to
`reunion_*_units`, one to `reunion_admins`. Fix: replace `SlugOrId` with a
`ReunionContext { user, reunion, is_ra, flash, tabs_for: fn(&str) -> ... }`
extractor that does the lot in one trip using a CTE join. Page handlers
shrink to ~10 lines each.

### 15. Templates use `onclick="fn('{{ id }}','{{ other }}')"` for everything
`templates/pages/activities.html`, `locations.html`, `expenses.html` all
build long inline `onclick` strings that interpolate UUIDs into JS source.
Two problems:
- Fragility: every quote, paren, or special character has to be hand-escaped.
  The "Schedule button" bug the user mentioned is a symptom of this pattern.
- HTML escape vs JS escape: Askama escapes for HTML attributes by default
  (which is fine for hex UUIDs), but the moment any of these args become
  user-controlled (a slug, a title) it becomes a stored-XSS vector.

Fix: convert to data attributes + delegated handlers in `app.js`. Example:
```html
<button data-action="toggle-rsvp" data-act-id="{{ a.idea.id }}"
        data-reunion-id="{{ reunion.id }}" data-rsvp="false" data-role="make">
```
Plus one document-level click handler in `app.js` that reads
`event.target.closest('[data-action]')`. Centralizes the surface and makes
the templates uniform.

### 16. `assets/app.css` dark-mode overrides are a maintenance trap
`assets/app.css:330-477` is 150 lines of `.dark .bg-amber-50 { ... }`
overrides. Each new colour the project adopts requires a manual override
here, and the colour values are hand-tuned per swatch. The Tailwind config
already supports `darkMode: 'class'` and `dark:` variants — the right answer
is to define a Tailwind theme that emits both light and dark variants from
the same token set, OR commit fully to CSS variables and ban
`bg-amber-100`-style raw utility classes in templates.
Fix: pick one and migrate. The current hybrid forces every contributor to
remember the override table, and `grep` for "bg-amber-100" returns 30+
template sites — when one is missed, dark mode silently breaks for that
chip. Recommend the CSS-variable route since the design system in
`app.css:7-46` is already variable-driven.

### 17. Templates reference Google Fonts CDN with no SRI / no fallback / no privacy
`templates/layout_app.html:81-83` pulls Atkinson Hyperlegible directly from
Google. CSP would block it, dropouts mean the site shows Comic Sans on
flaky networks, and every page view leaks user IP+UA to Google.
Fix: self-host the woff2 from `assets/` (and add a CSP). The `Assets`
embed already handles `woff2` MIME types (`src/routes/pages.rs:62`).

### 18. There are no integration tests at all
`tests/` directory exists but is empty (verified via `ls`). The unit tests
live inside the per-module `#[cfg(test)]` blocks and cover pure functions
(`calculate_even_split`, deserialization). Nothing exercises a DB roundtrip,
nothing exercises an HTTP handler, nothing catches the auth gaps in P0.
Fix: add `tests/api.rs` that spins up a Postgres testcontainer + the axum
app, registers two users in two family units, and asserts that user A
cannot read user B's reunion. That single test would have caught most of
P0 #1. Then add per-domain integration tests as bugs are fixed.

### 19. Pre-commit hook is opt-in and falls off on rebase
`CLAUDE.md:32-45` instructs new clones to `ln -sf .../pre-commit`. There
is no `cargo` build-script enforcement and no CI guard. The user has
already had migrations break twice (018 and 019 per the prompt). The hook
isn't enough — every fresh clone misses it.
Fix: add a CI step that runs the same byte-checksum check the hook does
(`git diff main -- migrations/*.sql` should be empty for committed files).
Add a `build.rs` that emits a `cargo:rerun-if-changed=migrations/` and
fails the build if any file in `migrations/` is newer than its checksum
stored in a tracked `migrations.lock` file. Belt-and-braces.

### 20. CSP is missing entirely
`src/main.rs:251-279` sets `X-Frame-Options`, `Referrer-Policy`,
`Permissions-Policy`, HSTS in production. No `Content-Security-Policy`. The
app loads Alpine.js from jsdelivr (`layout_app.html:84`) and fonts from
Google — a CSP would document and enforce that. Without it, any XSS that
slips past the templating (e.g. the `onclick=` data flow above) executes
freely.
Fix: add a CSP header. Start with
`default-src 'self'; script-src 'self' https://cdn.jsdelivr.net 'unsafe-inline'; style-src 'self' https://fonts.googleapis.com 'unsafe-inline'; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://lh3.googleusercontent.com https://avatars.githubusercontent.com`.
Then remove `'unsafe-inline'` once the `onclick=` cleanup (#15) is done.

## P2 — quality smells, fix opportunistically

### 21. `error.rs` returns JSON for errors thrown by HTML page handlers
`src/error.rs:62` always responds `Json(json!({ "error": message }))`. When
a page handler (e.g. `availability_page`) hits an `AppError::Database`, the
browser user sees `{"error":"database error"}` as plain JSON. Fix: make
`AppError::into_response` content-negotiate against the `Accept` header (or
split into `ApiError` vs `PageError` types). For pages, render an error
template with the flash banner.

### 22. `Phase` re-derived via raw `?` strings in dashboard query
`src/routes/pages.rs:1280-1297` uses `ai.status::text` in SQL and matches
strings ("scheduled","cancelled") in handlers/templates. The
`ActivityStatus` enum exists for exactly this — `sqlx::query_as` could
return the enum directly. Fix: drop `::text`, bind `ActivityStatus` in the
Rust struct.

### 23. `expenses.list_expenses` returns a different shape than the page view computes
The JSON endpoint returns `Vec<ExpenseWithSplits>` (`routes/expenses.rs:21-25`)
but the HTML page (`routes/pages.rs:1849-1879`) ignores splits and just
shows the dollar amount. Two views, two SQL paths, divergent. Fix: pick the
canonical model — probably `ExpenseWithSplits` — and have the HTML page
consume it too, so a UI change doesn't need to add a column to the API
separately.

### 24. `UnitBalance` and `BalanceView` are nearly identical
`src/models/expense.rs:48-52` defines `UnitBalance { family_unit_id, net_cents }`.
`src/routes/pages.rs:471-475` defines `BalanceView { family_name, net_cents, net_dollars }`.
The Rust naming convention is `UnitBalance` is the DB row and `BalanceView`
is the rendered shape — that's *fine*. The smell is that
`BalanceView::net_dollars` is computed inline in the handler (`pages.rs:1900`)
with manual `dollars.abs()` / `cents` math, and the same math is repeated
for `ExpensePageView::amount_str` (`pages.rs:1853-1857`). Fix: add a single
`fn format_cents(c: i64) -> String` helper in `src/models/expense.rs` and
call it from both sites.

### 25. `calendar_months` panics on degenerate ranges
`src/routes/pages.rs:213-263` has six `.unwrap()`s on `NaiveDate::from_ymd_opt`.
They are safe for any in-range date *today*, but if `start > end` the outer
loop never runs and that's silently a blank calendar — no error to the user.
Fix: assert `start <= end` at the top; return `Vec::new()` with a
`tracing::warn!` if violated. Also use `chrono`'s `Months::new(1)` for
month advancement so the `cur.month() == 12` special cases go away.

### 26. Migration 020 isn't crash-safe if the temp table truncate races
`migrations/020_expense_splits_by_family_unit.sql:23-28` does
`TRUNCATE expense_splits; ... INSERT INTO expense_splits SELECT ...`. SQLx
wraps the migration in a transaction (per the comment), so it's atomic
within itself — fine. But the design loses correlation between the original
`expense_splits.id` UUIDs and the new rows. Any FK that references
`expense_splits.id` (none today, but tomorrow?) is silently broken. Fix:
when writing migrations that recreate rows, use `UPDATE` not
`TRUNCATE`+`INSERT` whenever possible.

### 27. Migrations 018 and 019 deployed via manual checksum patching — root cause not addressed
The user mentioned both were deployed by hand-editing `_sqlx_migrations`.
Looking at the files: 018 has CRLF risk (mixed-pkey logic that's
sensitive to formatting), 019 is a one-liner that's hard to break. The root
cause is almost certainly Windows line-ending normalization on `git checkout`
even with `.gitattributes` enforced. Fix:
- Add a `cargo xtask check-migrations` (or shell script) that hashes each
  `*.sql` file and compares to a committed `migrations.lock`. Run it in CI
  and as the first step of `build.sh`.
- Document the recovery runbook (you have one — it should live in `CLAUDE.md`
  not in agent memory).

### 28. `SlugOrId` extractor returns `Redirect::to("/dashboard")` on missing reunion
`src/routes/pages.rs:139-156`: when a slug doesn't resolve, the user gets a
silent dashboard redirect instead of a 404. Confusing UX (am I logged out?
is the URL wrong? did the reunion get deleted?). Fix: render a "reunion not
found" page with a "back to dashboard" link.

### 29. Inline `<script>` blocks scattered across templates
The instruction set mentioned this; confirmed. e.g.
`templates/pages/activities.html` contains the `saveAndApply`, `toggleF`,
`toggleCard`, `openScheduleActivity`, `openEditAct`, `saveLocationVote`
functions (or fragments) inline. `app.js` has the global helpers but every
page adds its own. Fix: consolidate per-page JS into `assets/pages/*.js`
served via `Assets` embed, included from the template's `{% block scripts %}`.
Bonus: enables CSP without `'unsafe-inline'`.

### 30. `ProfileForm` and `UpdateMeRequest` duplicate avatar validation
`src/routes/pages.rs:1056-1064` (form path) and
`src/routes/auth.rs:51-59` (JSON path) both validate against
`ALLOWED_AVATAR_PREFIXES`. They drift independently. Fix: move
`is_allowed_avatar_url(&str) -> bool` to `src/auth/mod.rs` and use it from
both call sites.

### 31. `dashboard` does three separate fetches that could be one CTE
`src/routes/pages.rs:984-1009` queries `reunion_admins`,
`reunion_family_units`, `reunion_invite_members` separately, plus
`Reunion::list_all`, plus a join for admin display names. Five round trips
per dashboard load. Fix: one CTE that returns
`(reunion_id, accessible, is_ra, ra_names)` keyed on `user_id = $1`.

### 32. Test for `Expense::create` DB roundtrip is missing
`src/models/expense.rs:206-270` tests only the pure `calculate_even_split`.
The actual transactional path (`Expense::create`) — which is the part most
likely to break under concurrent writes or constraint violations — is
untested. Fix: add a `#[sqlx::test]` (or integration test) that creates a
reunion + family unit, inserts an expense with three splits, and asserts
the sum equals `amount_cents`.

### 33. `serde_json::to_string(&map).unwrap_or_else(|_| "{}".into())` everywhere
`src/routes/pages.rs:1442-1444, 1454-1455` etc. These can't actually fail
for `HashMap<String, i64>` — it's defensive `unwrap_or_else` against a
serialization error that's structurally impossible. Fix: use
`.expect("infallible: HashMap<String,i64> serializes")` so future

### 34. `pwd::generate_token()` used for session-bound CSRF — fine, but verify entropy

### 37. `reunion_overview` runs four sequential awaits that don't depend on each other
`src/routes/pages.rs:1228-1311`: `avail_response_count`, `member_count`,
`location_count`, `top_activity_rows`, `activity_total` — five separate

### 38. Missing index on `activity_rsvps.user_id`
Schema (`001_initial.sql` + `018`) indexes `(activity_idea_id, user_id, role)`
as PK. Queries like `helpers::meal_rsvp_names_for_block` join through
`activity_rsvps` and filter by `ar.user_id` patterns elsewhere. Postgres can
seek the PK only by leading column, so user-id-only lookups do a full scan.
Add `CREATE INDEX idx_activity_rsvps_user ON activity_rsvps(user_id);` in a
new migration.

### 39. `expense_splits` lost its old PK on user_id with no replacement index for `family_unit_id`
After migration 020, `expense_splits` has `UNIQUE(expense_id, family_unit_id)`
which serves the join in `balances_for_reunion`. Good. But queries that ever
need "all expenses charging family unit X" would have to seq-scan — add a
single-column index on `family_unit_id` if such queries appear.

### 40. The pre-commit hook docs say "lock symlink in"
Symlinks under `.git/hooks/` work poorly on Windows. The Windows path uses
`copy` (a copy, not a link), which means edits to
`scripts/git-hooks/pre-commit` don't propagate. Either commit a
`tools/install-hooks.{sh,ps1}` that re-copies, or use
`core.hooksPath = scripts/git-hooks` in a per-clone `.git/config` write
(documented next to the existing setup notes). The current state silently
diverges.
